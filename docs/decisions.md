# Decisions

## D-001: 証券会社別CSVは内部共通レコードへ正規化する

### 決定

野村・楽天などの入力CSV/スプレッドシートは、直接DBへ入れず、内部共通レコードへ正規化してから既存処理に流す。

### 理由

- 既存のDBスキーマと出力ロジックを再利用できる。
- 証券会社ごとの列差分を入力層に閉じ込められる。
- 楽天以外の証券会社追加にも対応しやすい。

## D-002: 楽天DBはUIに直接表示しない

### 決定

楽天専用DBは `uiVisible: false` とし、UIには出さない。UIで選ばれた `corp_a` / `corp_b` / `test` を、入力フォーマットに応じて内部的に `rakuten_*` へルーティングする。

### 理由

- UIの選択肢を増やしすぎない。
- ユーザーは法人やテストDBだけを選べばよい。
- 証券会社判定は入力ヘッダーから自動でできる。

## D-003: 楽天Phase 1は日本株・米国株のみ

### 決定

楽天対応は一度に全フォーマットを実装せず、Phase 1では日本株・米国株のみ対応する。

### 理由

- 楽天は日本株、米国株、投信、配当金、入出金でフォーマットが異なる。
- 先に株式取引の正規化とDBルーティングを安定させる。
- 投信・配当・入出金は別フェーズで仕様確認しながら進める。

## D-004: DB作成先フォルダを指定できるようにする

### 決定

`spreadsheetId` が空欄のDBは、`DB_CONFIG.DB_FOLDER_ID` で指定したDriveフォルダ内から検索し、見つからなければそのフォルダに作成する。

### 理由

- マイドライブ直下にDBが散らばるのを防ぐ。
- 複数法人・複数証券会社DBを整理しやすい。

### 注意

実際のフォルダIDはリポジトリへコミットしない。

## D-005: Webアプリはアクセスしているユーザーとして実行する方針

### 決定

現時点のユーザー方針は、Webアプリを「アクセスしているユーザー」として実行する運用。

### 理由

- 利用者本人の権限で実行したい。
- ただし、利用者本人にDBフォルダ編集権限とDrive OAuth承認が必要になる。

### 注意

Drive権限エラーが起こりやすいため、初回利用時の承認、フォルダ共有、新バージョン再デプロイを確認する。
