## 現在の目的

最新仕様として、取引履歴CSV / スプレッドシートをDBへ蓄積し、そのDB全体を正本として以下のシートを安定して生成する。

- 元データ
- 日本株
- 米国株
- 外債
- 投信

- 金銭残高（ドル）

特に以下を重視する。

- DBへの重複登録防止
- 別入力追加時の再生成整合性
- 平均取得単価の計算精度
- 簿価の計算基準の統一
- 銘柄ごとの残高のズレ防止
- 表示ルールと内部保持ルールの分離
- テストを回しながら安全に修正できる状態を保つ

## 現在の前提・確定事項

### 入力
- CSVリンク / スプレッドシートURLまたはID / ローカルCSVファイル をサポート
- 一次受け枠も同じ3系統から作成可能
- 手入力列は  
  `国内消費税等（円） / 現地源泉税（円） / 国内源泉所得税（円） / 国内源泉地方税（円） / 国内手数料（円） / 現地手数料（円） / 元本払戻金`

### 出力
- 6シート出力
- `外債` は `米国株` から分離
- 先頭側のタブ順は `日本株 → 米国株 → 外債 → 投信`
- 金銭残高は `円 / ドル` で分離

### 計算ルール
- 平均取得単価は内部小数保持、表示整数
- 簿価（現物売却・現物買取・強制償還（売））は `acquisitionPrice` を使う
- `bookValue = -acquisitionPrice`
- 強制償還（売）の `手数料抜き売値` は `受渡金額/決済損益`
- 償還は「一つ前の保有数が0かどうか」で分岐する
- `入金（分配金）` は簿価・銘柄ごとの残高を増やさない
- 外貨買付系の簿価は  
  `受渡金額 × レート - 手数料の消費税額 × レート`
- 現物売却 / 現物買取 / 強制償還（売） / 償還 で平均取得単価が無い場合は「平均取得単価が未計算」とアラート
- 平均取得単価そのものを先に丸めて別計算に使わない

### DB運用
- DB本体は `取引DB`
- 取込履歴は `取込履歴`
- 重複判定は `rowHash` ベース
- `rowHash` は取引内容から作る
- 別入力でも同じ取引ならスキップ対象
- Webアプリ入口は DB フローに接続済み
- `test DB` では赤セル必須入力バリデーションをスキップ可能
- `test DB` は固定確認用出力Spreadsheetへ再出力可能

### テスト運用
- 固定Spreadsheetを再利用
- 必要に応じてテスト用フォルダ配下で自動生成
- Script Properties は safer 版 + 自動 ensure を使う

## よくあるハマりどころ

- 末尾 `_` の関数は実行メニューに出ない
- ChatGPT のコードブロック記号をそのまま貼ると壊れる
- 部分差し替えで `{}` を壊しやすい
- writer テストは権限承認が必要
- 固定出力Spreadsheetを再利用していると、タブ順を明示的に揃えないと古い順序を引きずることがある
- テストだけ通って実データでズレることがある
- 結果画面で件数が見えていても、`取込履歴` 側で最終確認した方が安全
