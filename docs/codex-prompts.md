# Codex Prompt Templates

このファイルは、Codex Pro を前提にした依頼テンプレート集です。
以前の「使用量節約」寄りの運用から、**開発効率・検証・Draft PR作成までの自走**を重視する方針に変更しています。

## 使い方

Codex には、毎回長い説明を書かずに次のように依頼します。

```text
docs/codex-prompts.md の T02 を使って進めてください。

目的:
- 楽天配当金取込の警告件数が期待どおりになるようにしたい

対象ファイル候補:
- src/app/source_routing_rakuten_phase1.gs
- src/test/test_rakuten_phase1.gs

期待する挙動:
- 税額0は未入力警告にしない
- 空欄は未入力警告にする
```

## 基本方針

- Codex Pro 前提なので、明確な作業依頼では **調査 → 実装 → テスト → ドキュメント更新 → コミット → Draft PR作成** まで進めてよい。
- ただし、`develop` / `main` への直接コミット、Ready for review化、マージはしない。
- Secret、トークン、OAuth情報、実URL、実IDはコミットしない。
- 本番GAS、本番DB、本番Driveには触れない。
- 仕様変更、DBスキーマ変更、出力列変更、本番環境操作が必要になったら止まって確認する。
- 大きすぎる変更は、PR分割案を出してから進める。
- 調査だけで止めたい場合は、T01 または T03 を明示して使う。
- GitHub上で人間が読む文章は、原則として日本語で書く。対象はIssue/PRのタイトル・本文・コメント、レビューコメント、修正依頼、GitHub Actionsの手動実行時に記載する説明、Codexの作業報告。例外はコード、識別子、コマンド、ログ、エラーメッセージ、既存互換が必要なcheck名、英語表記のほうが明確な一般的技術用語。

## 作業開始時の共通確認

作業開始時は必要に応じて以下を読む。

- `AGENTS.md`
- `CLAUDE.md`
- `docs/current-status.md`
- `docs/TODO.md`
- 関連する仕様ドキュメント
- 対象PRの本文・差分・CI結果

## 共通の報告形式

作業完了時は次を報告する。

1. 変更したファイル
2. 変更概要
3. 実行したテスト
4. 未実行・未確認の項目
5. リスク
6. 次に人間が確認すべきこと
7. PRを作成した場合は PR URL / base / head

## T03: PRレビュー

```text
PR #{{PR番号}} をレビューしてください。まだコード変更はしないでください。

重点的に見る観点:
- 既存仕様との矛盾
- GAS / V8 で動かないコードがないか
- UIとサーバー側の引数名・戻り値名が合っているか
- DBキー変更による互換性破壊がないか
- テスト不足
- CIがgreenでもfalse positiveになっていないか
- マージ前に手動確認すべき項目

出力形式:
1. マージしてよいかの暫定判断
2. ブロッカー
3. できれば直したい点
4. 確認済みで問題なさそうな点
5. Codexに次に依頼すべき最小タスク
6. 人間が確認すべき操作
```
