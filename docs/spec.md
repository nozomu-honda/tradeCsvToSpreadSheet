# 取引履歴CSV 4シート生成 Webアプリ仕様書

## 1. 目的

取引履歴CSVを入力として、新しい Google スプレッドシートを作成し、以下の 4 シートを自動生成する。

- 国内取引
- 外国取引
- 金銭残高（円）
- 金銭残高（ドル）

また、1シート目には元データを `元データ` シートとして保存する。  
取り込んだデータは法人・口座単位のDBにも保存し、同じDBから再出力できるようにする。

---

## 2. 入力

### 2.1 入力方法

以下の 2 通りをサポートする。

- CSVリンク
- ローカルCSVファイルアップロード

Web UI では、CSV指定に加えて **追加先DB** を選択する。

### 2.2 必須列

CSVには少なくとも以下の項目が含まれることを前提とする。

- 約定日
- 受渡日
- 商品
- 銘柄名
- 取引区分
- 受渡金額/決済損益

通常は以下の基本列を持つCSVを想定する。

- 約定日
- 受渡日
- 商品
- 銘柄コード
- 銘柄名
- 摘要
- 取引区分
- 預り区分
- 発行通貨
- 数量
- 単価
- 受渡金額/決済損益
- 手数料（税込）
- レート
- 決済通貨
- 売買損益（円）

### 2.3 手入力用の追加列

野村證券のCSVには存在しなくてもよいが、手入力列として以下を許可する。

- 国内消費税等（円）
- 現地源泉税（円）
- 国内源泉所得税（円）
- 国内源泉地方税（円）

### 2.4 ヘッダー行の扱い

- 実データのヘッダー行は 1 行目固定ではない
- `取引履歴`、抽出条件、`明細数：xxx件` などの前置き行は許可する
- 1つ目の実データヘッダーより前に実データ行がある場合はエラー
- データ途中に実データヘッダーが再出現した場合はエラー

### 2.5 追加列ヘッダー名の厳密一致

手入力用の追加列を使う場合、ヘッダー名は以下と**完全一致**でなければならない。

- 国内消費税等（円）
- 現地源泉税（円）
- 国内源泉所得税（円）
- 国内源泉地方税（円）

例えば以下はエラーにする。

- 国内消費税等(円)
- 国内消費税等
- 国内源泉地方税(円)

追加列を使わない場合は、列自体が存在しなくてもよい。

## 3. DB運用

### 3.1 DBの考え方

- 法人・口座単位でDBスプレッドシートを分割する
- Web UIで追加先DBを選択してから取り込む
- 取込時は、CSVから読み取ったレコードを選択中DBの `取引DB` シートへ追加する
- 出力4シートは、選択中DBの有効レコードをもとに生成する

### 3.2 重複判定

同一DB内では、レコード内容から生成した `rowHash` により重複判定する。  
同一内容のレコードは追加せず、スキップ件数として扱う。

### 3.3 取込履歴

DBには `取込履歴` シートを持ち、少なくとも以下を保持する。

- importId
- importedAt
- targetDbKey
- targetDbLabel
- sourceName
- inputType
- normalizedUrl
- rowCount
- insertedCount
- skippedCount
- alertCount
- isRolledBack
- rolledBackAt
- rolledBackRecordCount

### 3.4 ロールバック

- ロールバックは `importId` 単位で行う
- ロールバック対象一覧は、選択中DBの最近の取込だけを表示する
- ロールバック方式は**論理削除**とする
- ロールバック時は、対象レコードの `isActive` を `false` にし、`updatedAt` と `rolledBackAt` を更新する
- `取込履歴` 側にも `isRolledBack`、`rolledBackAt`、`rolledBackRecordCount` を記録する

### 3.5 DBリセット

- Web UI から選択中DBをリセットできる
- リセット時は `取引DB` と `取込履歴` のシートを作り直し、ヘッダーのみ残す
- 値だけでなく、列書式・条件付き書式・残存フォーマットも初期化する

## 4. 出力シートの分類条件

| 出力シート | 条件 |
|---|---|
| 国内取引 | 商品が `株式` または `投信` |
| 外国取引 | 商品が `外株` または `外債` |
| 金銭残高（円） | 決済通貨が `JPY` または空欄 |
| 金銭残高（ドル） | 決済通貨が `USD` |

また、以下はアラート対象とする。

- 商品が `株式` / `投信` / `外株` / `外債` / `現金` のいずれでもない場合
- 決済通貨が `JPY` / `USD` / 空欄 のいずれでもない場合

`現金` は国内取引 / 外国取引には分類せず、金銭残高シート側で扱う。

---

## 5. 並び順

### 5.1 国内取引 / 外国取引

以下の順で昇順ソートする。

1. 商品
2. 銘柄名
3. 受渡日
4. 約定日
5. 取引区分優先順位

取引区分優先順位は `trade-rules.md` の定義に従う。  
また、銘柄名が切り替わる位置に空白行を 1 行入れる。

### 5.2 金銭残高（円） / 金銭残高（ドル）

以下の順で昇順ソートする。

1. 受渡日
2. 約定日
3. 銘柄名

---

## 6. 出力列

### 6.1 国内取引 / 外国取引

基本列に加えて、以下の列を追加する。

1. 保有数
2. 手数料の消費税額
3. 平均取得単価
4. 手数料抜き売値
5. 取得価格
6. 売却損益
7. 簿価
8. 銘柄ごとの残高
9. FX2の期末簿価

### 6.2 金銭残高（円） / 金銭残高（ドル）

基本列に加えて、以下の列を追加する。

1. 残高
2. 月次残高

### 6.3 手入力列の出力

以下の手入力列は、基本列の一部としてそのまま出力シートへ出す。

- 国内消費税等（円）
- 現地源泉税（円）
- 国内源泉所得税（円）
- 国内源泉地方税（円）

---

## 7. 税関連の扱い

### 7.1 国内消費税等（円）

`国内消費税等（円）` に値がある場合は、その値を **手数料の消費税額** に代入する。  
値がない場合のみ、従来どおり `手数料（税込）` から計算する。

### 7.2 現地源泉税（円） / 国内源泉所得税（円） / 国内源泉地方税（円）

- 入力を受け付ける
- DBに保持する
- 出力シートにそのまま出す
- **現時点では各種計算には使用しない**

---

## 8. 金銭残高の計算

### 8.1 残高

累積計算する。

| 取引区分 | 計算 |
|---|---|
| 現物買付 / 現物再投 / 出金（振込） / 現物募集 / 為替買付 | `受渡金額 × (-1)` |
| 現物売却 / 現物買取 / 入金（利金） / 入金（配当金） / 償還 / 入金（振込） / 入金（分配金） / 為替売却 | `受渡金額` |
| その他 | 何もしない |

### 8.2 月次残高

- その行がその月の最後の行なら残高を入れる
- それ以外は空欄

---

## 9. 表示ルール

- 保有数 0 は `0表示 + 赤字`
- 手数料 0 は `0表示`
- 平均取得単価は `内部小数保持 / 表示整数`
- 銘柄ごとの残高は整数表示
- 金額列は基本的に整数表示
- レートは小数表示
- その銘柄の最後の取引行で、保有数が 0 より大きい場合、銘柄名セルを水色にする

---

## 10. 非表示列

### 10.1 国内取引

- 摘要
- 発行通貨
- レート
- 決済通貨

### 10.2 外国取引

- 摘要

---

## 11. アラート出力

Webアプリの実行結果画面にアラートログを表示する。

### 11.1 アラート対象

- 簿価計算時のレート未入力
- 対象外の取引区分
- 必要な前提値が無く計算できないケース
- 現物売却 / 現物買取 / 強制償還（売） / 償還 で平均取得単価が無いケース
- 未対応の商品
- 未対応の決済通貨
- 追加列のヘッダー名が完全一致していないケース

### 11.2 アラート文の要件

以下が分かる形式にする。

- どの項目の判定で起きたか
- 取引区分
- 銘柄名
- 受渡日
