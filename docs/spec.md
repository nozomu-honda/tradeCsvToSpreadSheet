# 取引履歴CSV / スプレッドシート 6シート生成 Webアプリ仕様書

## 1. 目的

取引履歴CSVまたは取引履歴を持つスプレッドシートを入力として、新しい Google スプレッドシートを作成し、以下の **6 シート** を自動生成する。

- 日本株
- 米国株
- 外債
- 投信
- 金銭残高（円）
- 金銭残高（ドル）

また、成果物には `元データ` シートを保持する。  
取り込んだデータは法人・口座単位のDBにも保存し、同じDBから再出力できるようにする。

---

## 2. 入力

### 2.1 入力方法

以下の 3 通りをサポートする。

- CSVリンク
- スプレッドシートURLまたはID
- ローカルCSVファイルアップロード

Web UI では、入力元指定に加えて **追加先DB** を選択する。

### 2.2 必須列

入力には少なくとも以下の項目が含まれることを前提とする。

- 約定日
- 受渡日
- 商品
- 銘柄名
- 取引区分
- 受渡金額/決済損益

通常は以下の基本列を持つ入力を想定する。

- 約定日
- 受渡日
- 商品
- 銘柄コード
- 銘柄名
- 摘要
- 取引区分
- 預り区分
- 発行通貨
- 数量
- 単価
- 受渡金額/決済損益
- 手数料（税込）
- レート
- 決済通貨
- 売買損益（円）

### 2.3 手入力用の追加列

野村證券の元CSVには存在しなくてもよいが、手入力列として以下を許可する。

- 国内消費税等（円）
- 現地源泉税（円）
- 国内源泉所得税（円）
- 国内源泉地方税（円）
- 国内手数料（円）
- 現地手数料（円）
- 元本払戻金

### 2.4 手入力列の入力仕様

- `元本払戻金`
  - 入力値は **空欄 または 1**
  - 内部では **null 許容 boolean** として保持する
- `国内手数料（円）`
  - 数値または空欄
- `現地手数料（円）`
  - 数値または空欄
- `国内消費税等（円）`
  - 数値または空欄
- `現地源泉税（円）`
  - 数値または空欄
- `国内源泉所得税（円）`
  - 数値または空欄
- `国内源泉地方税（円）`
  - 数値または空欄

### 2.5 ヘッダー行の扱い

- 実データのヘッダー行は 1 行目固定ではない
- `取引履歴`、抽出条件、`明細数：xxx件` などの前置き行は許可する
- 1つ目の実データヘッダーより前に実データ行がある場合はエラー
- データ途中に実データヘッダーが再出現した場合はエラー

### 2.6 追加列ヘッダー名の厳密一致

手入力用の追加列を使う場合、ヘッダー名は以下と**完全一致**でなければならない。

- 国内消費税等（円）
- 現地源泉税（円）
- 国内源泉所得税（円）
- 国内源泉地方税（円）
- 国内手数料（円）
- 現地手数料（円）
- 元本払戻金

追加列を使わない場合は、列自体が存在しなくてもよい。

## 3. 一次受け枠

### 3.1 作成方法

一次受け枠は以下の入力から作成できる。

- CSVリンク
- スプレッドシートURLまたはID
- ローカルCSVファイルアップロード

### 3.2 出力内容

- シートは 1 枚のみ作成する
- シート名は `取引履歴_一次受け枠`
- 元のヘッダー末尾に追加7カラムを付ける

### 3.3 色付け

#### 外株

- `決済通貨 = USD` の場合  
  - `レート` を赤
- `取引区分 = 現物買付 / 現物売却` の場合  
  - `国内手数料（円）` を赤  
  - `国内消費税等（円）` を赤  
  - `現地手数料（円）` を赤
- `取引区分 = 入金（配当金） / 入金（分配金）` の場合  
  - `現地源泉税（円）` を黄  
  - `国内源泉所得税（円）` を赤  
  - `国内源泉地方税（円）` を黄

#### 投信

- `取引区分 = 現物売却 / 現物買取` の場合  
  - `国内源泉所得税（円）` を黄  
  - `国内源泉地方税（円）` を黄
- `取引区分 = 入金（分配金）` の場合  
  - `国内源泉所得税（円）` を黄  
  - `国内源泉地方税（円）` を黄  
  - `元本払戻金` を黄

### 3.4 必須入力バリデーション

赤セルは必須入力とする。  
一次受け枠から本処理へ進む際、赤セルが空欄ならエラーで停止する。

ただし、**test DB** を選択した場合は、この必須入力バリデーションをスキップできる。

## 4. DB運用

### 4.1 DBの考え方

- 法人・口座単位でDBスプレッドシートを分割する
- Web UIで追加先DBを選択してから取り込む
- 取込時は、入力から読み取ったレコードを選択中DBの `取引DB` シートへ追加する
- 出力6シートは、選択中DBの有効レコードをもとに生成する

### 4.2 DBターゲット

少なくとも以下を持つ前提とする。

- 本番A
- 本番B
- test DB

### 4.3 重複判定

同一DB内では、レコード内容から生成した `rowHash` により重複判定する。  
同一内容のレコードは追加せず、スキップ件数として扱う。

### 4.4 取込履歴

DBには `取込履歴` シートを持ち、少なくとも以下を保持する。

- importId
- importedAt
- targetDbKey
- targetDbLabel
- sourceName
- inputType
- normalizedUrl
- rowCount
- insertedCount
- skippedCount
- alertCount
- isRolledBack
- rolledBackAt
- rolledBackRecordCount

### 4.5 ロールバック

- ロールバックは `importId` 単位で行う
- ロールバック対象一覧は、選択中DBの最近の取込だけを表示する
- ロールバック方式は **論理削除**
- ロールバック時は、対象レコードの `isActive` を `false` にし、`updatedAt` と `rolledBackAt` を更新する
- `取込履歴` 側にも `isRolledBack`、`rolledBackAt`、`rolledBackRecordCount` を記録する

### 4.6 DBリセット

- Web UI から選択中DBをリセットできる
- リセット時は `取引DB` と `取込履歴` のシートを作り直し、ヘッダーのみ残す
- 値だけでなく、列書式・条件付き書式・残存フォーマットも初期化する

### 4.7 test DB の特例

- `test DB` では、赤セル必須入力バリデーションをスキップできる
- `test DB` の成果物出力は、固定の確認用スプレッドシートへ上書き出力できる
- 通常DBでは都度新規作成、test DB では固定出力先再利用、という運用を許可する

## 5. 出力シートの分類条件

| 出力シート | 条件 |
|---|---|
| 日本株 | 商品が `株式` |
| 米国株 | 商品が `外株` |
| 外債 | 商品が `外債` |
| 投信 | 商品が `投信` |
| 金銭残高（円） | 決済通貨が `JPY` または空欄 |
| 金銭残高（ドル） | 決済通貨が `USD` |

また、以下はアラート対象とする。

- 商品が `株式` / `投信` / `外株` / `外債` / `現金` のいずれでもない場合
- 決済通貨が `JPY` / `USD` / 空欄 のいずれでもない場合
- 想定していない取引区分がある場合

`現金` は日本株 / 米国株 / 外債 / 投信には分類せず、金銭残高シート側で扱う。

## 9. 税・手数料・元本払戻金の扱い

### 9.1 国内消費税等（円）

`国内消費税等（円）` に値がある場合は、その値を **手数料の消費税額** に代入する。  
値がない場合のみ、従来どおり `手数料（税込）` から計算する。

### 9.2 現地源泉税（円） / 国内源泉所得税（円） / 国内源泉地方税（円）

- 入力を受け付ける
- DBに保持する
- 出力シートにそのまま出す
- **現時点では各種計算には使用しない**

### 9.3 国内手数料（円） / 現地手数料（円）

- 入力を受け付ける
- DBに保持する
- 出力シートにそのまま出す
- **現時点では各種計算式には未反映**
- 将来の計算拡張用の入力枠として扱う

### 9.4 元本払戻金

- 空欄または `1` を受け付ける
- 内部では null 許容 boolean として保持する
- `true` の場合も、`入金（分配金）` 自体は簿価・残高を増やさない
- 詳細ルールは `trade-rules.md` を正とする

---

## 10. 金銭残高の計算

### 10.1 残高

累積計算する。

| 取引区分 | 計算 |
|---|---|
| 現物買付 / 現物再投 / 出金（振込） / 現物募集 / 為替買付 | `受渡金額 × (-1)` |
| 現物売却 / 現物買取 / 入金（利金） / 入金（配当金） / 償還 / 入金（振込） / 入金（分配金） / 為替売却 | `受渡金額` |
| その他 | 何もしない |

### 10.2 月次残高

- その行がその月の最後の行なら残高を入れる
- それ以外は空欄

## 11. 表示ルール

- 保有数 0 は `0表示 + 赤字`
- 手数料 0 は `0表示`
- 平均取得単価は `内部小数保持 / 表示整数`
- 銘柄ごとの残高は整数表示
- 金額列は基本的に整数表示
- レートは小数表示
- その銘柄の最後の取引行で、保有数が 0 より大きい場合、銘柄名セルを水色にする

## 14. アラート出力

Webアプリの実行結果画面にアラートログを表示する。

### 14.1 アラート対象

- 簿価計算時のレート未入力
- 対象外の取引区分
- 必要な前提値が無く計算できないケース
- 現物売却 / 現物買取 / 強制償還（売） / 償還 で平均取得単価が無いケース
- 未対応の商品
- 未対応の決済通貨
- 追加列のヘッダー名が完全一致していないケース

### 14.2 アラート文の要件

以下が分かる形式にする。

- どの項目の判定で起きたか
- 取引区分
- 銘柄名
- 受渡日
